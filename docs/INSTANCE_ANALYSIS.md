# 인스턴스 전수 분석 — 40개 공개 테스트 케이스의 원자단위 라벨링

이 문서는 `train/prob_1.json ~ prob_40.json` 40개를 원자단위로 분해해 라벨링한 것입니다. [LEARNING_GUIDE A3](./LEARNING_GUIDE.md)가 20개로 내린 "학습 인스턴스가 말해주는 것"을 40개로 확장하고, 일부는 **갱신**합니다. 모든 숫자는 인스턴스 파일을 직접 파싱해 측정한 값이며, 신규 인스턴스(prob_21~40)가 들어오면서 바뀐 결론은 본문에서 명시적으로 표시합니다. 전략적 함의는 마지막 절에 모았고, [STRATEGY_PLAN A2](./STRATEGY_PLAN.md)의 "측정된 현재 위치"와 연결됩니다.

작업 전에 이 문서를 먼저 둔 이유는 단순합니다 — P1의 fallback 구성자도, 종료 기준(DoD)도, 래스터 엔진의 메모리 산정도, 결국 *각 인스턴스가 무엇으로 이루어졌는지*를 정확히 알아야 설계됩니다. 추측이 아니라 측정 위에 서기 위한 바닥 문서입니다.

---

## 1. 원자 구조 — 인스턴스 하나의 해부

인스턴스 JSON은 네 개의 최상위 키로 이루어지고, 각 원자 필드는 정확히 하나의 목적함수나 제약으로 흘러 들어갑니다. 이 대응을 먼저 못박아 둡니다.

```
instance
├─ name : str                                    # 인스턴스 ID
├─ bays[ n_bays ] : { width:int, height:int }    # 정수 격자 베이 — 패킹 공간
├─ blocks[ n_blocks ]
│    ├─ release_time : int                       # 진입 가능 최소 시각 (제약: entry_time ≥ release_time)
│    ├─ due_date : int                           # 이 시각 이후 EXIT 1일당 obj1(지각) 누적
│    ├─ processing_time : int                    # 체류 기간 (exit_time − entry_time ≥ proc)
│    ├─ workload : int                           # → obj2(베이별 부하 균형)에만 기여
│    ├─ bay_preferences : list[int]              # → obj3(선호) — 선호 베이 인덱스 목록
│    └─ shape[ n_orient ] : { orientation:int, layers[][ [x,y]… ] }
│                                                # 방향 후보 × 레이어 × 다각형(실수 정점)
└─ weights : { w1:int, w2:int, w3:int }          # obj = w1·지각 + w2·불균형 + w3·선호손실
```

핵심 관찰 두 가지가 여기서 이미 보입니다. 첫째, **obj2와 obj3은 `workload`와 `bay_preferences`만의 함수** — 즉 "어느 베이에 보냈는가"라는 할당만으로 결정되고 위치·시각과 무관합니다. **obj1만 패킹·스케줄에 의존**합니다. 이 분리가 STRATEGY B3의 2층 분해의 근거입니다. 둘째, **`shape`의 다각형 정점은 실수**입니다(아래 4.3). `release_time`·`due_date`·`processing_time`·`workload`는 정수지만, 블록의 윤곽선 좌표는 그렇지 않습니다.

## 3. 집계와 범위 — A3 갱신

40개 전체의 원자 범위입니다. 괄호 안은 A3(20개) 대비 변화입니다.

- **블록 수** 100–300, **베이 수** 2–5 (변화 없음).
- **단일 베이 최대** 179×29, 최대 **4,872셀** (A3의 "약 180×29 ≈ 5,220셀" 범위 안 — premise 유지).
- **시간 지평**(최대 due_date) 53–150 (A3의 "약 160일" 이내 — 유지).
- **다층 블록 비율** 80–100%, 중앙값 약 85% (A3 "86%, 81–98%"와 일치, 하한이 80%로 소폭 확장).
- **최대 레이어 수** 2–4. 방향 후보 수 블록당 2–8.
- **레이어 다각형 정점** 3–12개(평균 약 7). 한 블록은 방향당 2–4개의 레이어 다각형을 가집니다.
- **슬랙** 전 블록 0–14 (★ A3 "0–5"에서 **확장** — 4.1 참조). 평균 2.37. **음수 슬랙 0건** — 어떤 블록도 자기 납기를 구조적으로 어기지 않습니다.
- **가중치** w1 667–29,630, w2 1–10, w3 13–600 (★ A3 "w1 8,889–29,630 / w2 4–10 / w3 125–200"에서 **대폭 확장** — 4.2 참조).

크기 봉투(블록·베이·단일 베이 셀·시간 지평)는 신규 인스턴스가 들어와도 **넓어지지 않았습니다.** 즉 래스터 엔진(STRATEGY B2/P2)의 메모리·시간 산정은 40개 전부에 대해 그대로 유효합니다. 신규 인스턴스가 바꾼 것은 *크기*가 아니라 *성격* — 슬랙과 가중치의 다양성입니다.

## 4. A3를 뒤집는 세 가지 발견

### 4.1 슬랙 — "전부 타이트"는 깨졌다. 두 패밀리가 있다

A3는 "슬랙이 모든 블록에서 0–5일에 불과하다 → 사실상 지각 최소화 패킹"이라고 결론지었습니다. 이는 **prob_1~20에 대해서는 여전히 정확합니다**(전부 sl_max 4–5). 그러나 **prob_21~40은 sl_max가 7–14**로, 블록에 실질적인 스케줄 자유도가 있는 **여유 패밀리**입니다.

이 차이는 알고리즘의 성격을 바꿉니다. 타이트 패밀리에서는 "넣을 수 있느냐"가 곧 "지각이 없느냐"이므로 순수 패킹 능력이 점수입니다. 여유 패밀리에서는 같은 블록을 며칠 미뤄 넣어도 지각이 없으므로, 그 자유도를 obj2(부하 균형)와 obj3(선호) 개선에 쓸 수 있습니다. **타이트에서 통하는 욕심쟁이 배치가 여유에서는 obj2·obj3을 낭비**할 수 있습니다.

다만 여유 패밀리에서도 `slack0`(구속 블록)은 여전히 존재합니다(prob_39는 250개 중 53개). 인스턴스 안에 구속 블록과 자유 블록이 섞여 있다는 뜻이고, 둘을 다르게 다뤄야 합니다 — 구속 블록은 시각이 거의 고정이고, 자유 블록이 할당 최적화의 여지를 줍니다.

### 4.2 가중치 — "지각이 모든 걸 지배한다"가 일부 인스턴스에서 깨졌다

A3는 w1(지각)이 w3(선호)보다 압도적이라 "지각이 0에 수렴한 다음에야 obj3 싸움이 시작된다"고 했습니다. 신규 인스턴스 대부분에서는 여전히 맞습니다(w1/w3 ≥ 33). 그러나 **세 인스턴스가 예외**입니다.

**prob_32·34·37은 w1/w3 ≈ 5.6–6.3**입니다. 지각 한 단위가 선호 손실 한 단위의 6배밖에 안 됩니다. 이 인스턴스에서는 "선호를 약간 포기해 지각을 줄이는" 거래가 더 이상 자명하지 않습니다 — 선호 손실이 지각 절감을 상쇄할 수 있습니다. **지각만 보는 알고리즘은 이 세 인스턴스에서 obj3을 흘립니다.** 모두가 지각 0을 달성하는 쉬운 인스턴스에서는 strictly-better 동점 규칙(A1) 때문에 이 obj3 한 자리가 순위를 가릅니다. 즉 이 세 인스턴스는 **차별화가 점수로 직결되는 지점**입니다.

또 하나의 결: **prob_25·36·40은 w1=667**로 모든 가중치의 절대 크기가 작습니다(w3 13–20, w2 1). 목적값의 스케일이 다른 인스턴스의 1/40 수준이라, 점수 함수를 인스턴스 가중치로 정규화하지 않으면(베이스라인 `_placement_score`의 임의 상수 문제, GUIDE B4) 튜닝이 인스턴스 간에 옮겨가지 않습니다. **점수 함수는 반드시 w1·w2·w3로 정규화**해 둬야 합니다.

### 4.3 좌표 정수 — 정확히 무엇이 정수인가

A3와 B2는 "좌표와 시각이 모두 정수라서 래스터 엔진이 성립한다"고 합니다. 이 문장은 **해(출력)의 배치 좌표와 시각**에 대한 것입니다. 실제로 측정해 보면 **입력 다각형의 정점은 실수**입니다 — 예: `(3.917, -0.336)`, `(-9.934, 0.224)`. 40개에서 약 69만 개의 정점이 비정수이고, 음수 좌표도 흔합니다(다각형이 원점 주위 국소 좌표계로 정의되기 때문).

이것은 모순이 아니라 **보수적 래스터의 존재 이유**입니다. 블록은 정수 위치 `(x, y)`에 놓이지만, 그 블록의 윤곽선은 격자에 맞아떨어지지 않습니다. 그래서 C2의 래스터는 "걸치는 셀은 1로" 보수화해야 하고(안전한 방향으로만 틀림), 최종 판정은 항상 실수 기하를 보는 Shapely(utils)가 합니다. 우리 알고리즘이 다각형 정점을 정수로 가정하고 스냅하면 — 미세하게 위치가 어긋나 stage 4에서 충돌 판정을 받습니다. **다각형은 실수, 배치 격자는 정수**: 이 둘을 절대 혼동하지 않습니다.

## 5. 군집과 라벨

전수 표의 `라벨`을 묶으면 다섯 개의 축이 나옵니다. 알고리즘 파라미터를 인스턴스에 적응시킬 때(STRATEGY C2의 적응화) 이 라벨이 분기 조건이 됩니다.

- **슬랙 체제** — 타이트(prob_1~20, sl_max≤5) vs 여유(prob_21~40, sl_max≥7). 순수 패킹 대 할당 여유.
- **선호경합** — prob_32·34·37(w1/w3≤7). obj3을 의식적으로 지켜야 하는 인스턴스.
- **저배율** — prob_25·36·40(w1=667). 정규화된 점수 함수가 없으면 튜닝이 깨지는 인스턴스.
- **고층** — prob_9·10·14·24·26·32·40(레이어 4, ml 96–100%). temporal nesting(STRATEGY B4)의 자유도가 가장 큰 인스턴스 — 차별화 효과 측정의 1순위 후보.
- **규모** — 소(100블록), 중(150–200), 대(250–300, prob_17·20이 단일 베이 최대). 시간·메모리 스케일 테스트의 상한.

## 6. 전략적 함의 — 계획 갱신

이 분석이 STRATEGY_PLAN의 결정과 단계에 미치는 영향입니다.

- **P1 종료 기준을 40개로 재정의.** 문서의 "20개 × 네 제한시간 invalid 0건"은 작성 당시 20개 기준입니다. 현 train이 40개이므로 DoD는 **40개 × 네 제한시간**입니다. 기준런(`results/baseline_60s/`)도 20개만 덮으므로, 비교가 성립하려면 40개 기준선을 새로 떠야 합니다. fallback 구성자는 최대 규모(300블록·5베이·단일 베이 179×29)에서도 시간 안에 끝나야 합니다.
- **B3(탐색)의 우선순위 조정.** "사실상 지각 최소화 패킹"이라는 단일 프레임은 타이트 패밀리에만 맞습니다. 여유 패밀리(절반)와 선호경합 인스턴스에서는 **할당 최적화(외층 obj2+obj3)가 처음부터 점수에 직접 기여**합니다. 2층 분해의 외층을 "지각 0 이후의 사치"가 아니라 여유 패밀리의 1차 목표로 다뤄야 합니다.
- **B2(래스터) premise 유지.** 크기 봉투가 안 커졌으므로 메모리·속도 산정은 그대로입니다. 좌표 실수성(4.3)은 보수 래스터 + Shapely 최종 판정 설계를 다시 한 번 정당화합니다.
- **B4(차별화) 측정 대상 지정.** 고층 군집(prob_9·10·14·24·26·32·40)이 temporal nesting ablation의 1순위 인스턴스입니다 — 자유도가 가장 크니 효과도 가장 크게 측정될 것입니다.
- **점수 함수 정규화는 비협상.** 저배율 인스턴스(4.2)가 증명하듯, 점수 함수의 모든 상수는 w1·w2·w3로 정규화해야 인스턴스 간 이식성이 생깁니다.
- **리스크(C2) 업데이트.** 히든이 학습보다 클 위험은 여전하지만, 신규 20개는 *크기*가 아니라 *성격*을 넓혔습니다. 따라서 적응화의 분기 축은 크기뿐 아니라 **슬랙 체제와 가중치 비율**이어야 합니다(5절의 라벨).
